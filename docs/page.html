Heatmiser neoHub, without the cloud

Whole home comfort, on your own network

neoHub is a small Windows tray app that finds your Heatmiser neoHub, talks to it directly over the house Wi-Fi, and serves a dashboard to every phone, tablet and PC at home. No account, no internet dependency, nothing leaves the building.

How it works

Three parts, one small program

The neoHub has a local control port that the Heatmiser app itself uses when you are at home. neoHub speaks to that port directly, which is why nothing here depends on Heatmiser's servers.

Tray app

neoHub.exe

Starts with Windows, sits in the tray, and runs a tiny web server. One file, written in Go, with the dashboard and its photos compiled in.

→
Hub link

Port 4242

Every click becomes a JSON command on the hub's legacy local port. Commands run one at a time, because the hub dislikes company.

→
Dashboard

Any browser

Served to the whole home network on port 8484. Add it to a phone's home screen and it behaves like an app.

Finding the hub

On start the app tries the hub's last address, then sweeps each local subnet for anything answering the hub protocol. It re-checks every minute and searches again if the hub goes quiet.

Reading the house

Live data, system settings, engineer settings, profiles and holiday state are fetched together and cached for four seconds, so a page full of controls costs the hub only one round of questions.

Keeping a diary

Once a minute the app notes which thermostats are offline, whether the hub's time sync is running, and whether the hub answered at all. Only changes are written, plus a heartbeat every ten minutes.

The dashboard

A tour of the tabs

Screenshots are from the live installation.

Overview

The whole house at a glance

  • Greeting line changes with the time of day and sums up the house: everything in standby, a few rooms heating, away or holiday mode on.
  • Heat all zones and All to standby act on every thermostat at once. Standby means frost protection only, so the house will not drop below 12 °C.
  • One card per zone with the current temperature, the set point and a state chip. Hover a card for quick plus, minus and standby buttons; click it to open the zone.
  • Status dot in the top bar turns amber if the hub's time sync has stopped and red if a thermostat is offline.
Zones

Everything about one room

  • Zone strip across the top: every room in a row, underlined when selected, fading at the edges with arrows when it overflows.
  • Last 24 hours as a temperature chart. The thermostat keeps a reading every 15 minutes; hover for the value at any point.
  • Controls: set temperature, a timed hold, standby, keypad lock, rename, and which stored profile the room follows.
  • Engineer settings: frost temperature, switching differential, output delay, max preheat, floor limit and user limit, each saved individually.
  • Device information: model, serial number, sensor mode, the stat's own clock and when its settings last changed.
Schedules

A room's own weekly programme

  • Four comfort levels per period: wake, leave, return and sleep, each a time and a temperature. The hub is in 5 day / 2 day mode, so there is a weekday row and a weekend row.
  • Save writes the levels to that thermostat. Copy to other zones pushes the same programme to any rooms you pick.
  • Profile warning: a room that follows a stored profile shows it. Saving its own levels takes it off the profile, and the Zones tab can put it back.
Profiles

Programmes shared by several rooms

  • Profile strip lists the programmes stored on the hub; one shows at a time in the same table layout as Schedules.
  • Used by pills show which rooms follow it, so you can see the effect of a change before making it.
  • Apply to zones, Rename and Delete, plus a form to store a new profile.
Hub quirk. When a 5 day / 2 day profile is stored, the hub writes the weekend row over the weekday row as well, so a new profile ends up with the weekend values in both periods. The form says so. A room's own comfort levels are not affected.
Hub

The hub itself

  • Time: the hub's clock against this device's, the NTP client, time zone and daylight saving. One button syncs the hub's clock from the PC.
  • Modes: away, holiday with start and end, schedule format, temperature unit, and a button that flashes the hub's LED so you can find it in the cupboard.
  • Hub information: the address discovery found, firmware, ZigBee channel (changeable, with a warning that every stat re-joins), and when the device list, profiles and settings last changed.
  • Open on your phone: the QR code and address for other devices.
History

Who dropped off, and when

  • Timeline with one bar per device: the hub, its time sync and every thermostat. Green is online, red offline, amber low battery, hatched grey means the dashboard was not running.
  • Ranges from six hours to thirty days or everything, scrolling sideways by drag or scrollbar, starting at now. Hover a bar for the state and its duration.
  • Events such as "Hallway went offline, 29 min" and "NTP time sync back running", and totals of drop-outs and time offline per device.
  • This is the tab that answers "is it the hub, the Wi-Fi, or one bad thermostat?"
Phones and tablets

Scan, then add to the home screen

The tray menu's "QR code for phones", and the panel at the bottom of the Hub tab, show a code for the dashboard's address on your home network. The app picks the address on the same network as the hub, so a VPN adapter is never offered first.

On an iPhone

Open the camera, point it at the code and tap the link. In Safari tap Share, then "Add to Home Screen". It installs with the flame icon and opens full screen without the browser bars.

On Android

Scan with the camera or Google Lens, open the link in Chrome, then use the menu's "Add to Home screen" or "Install app".

Installing

One installer, nothing else to set up

What the installer does

  • Copies neoHub.exe to Program Files and adds Start-menu shortcuts.
  • Offers to start neoHub at sign-in and to add the Windows Firewall rule that lets other devices reach port 8484.
  • Retires the earlier Node-based version if it was set up.
  • Starts the app and opens the dashboard when it finishes.

Day to day

  • The tray icon's menu: Open dashboard, QR code for phones, the hub it found, Find hub again, Start with Windows, Quit.
  • Settings, the connectivity diary and a log live in %LOCALAPPDATA%\neoHub.
  • Upgrading is running the new installer over the top. Settings and history are kept.
  • Windows SmartScreen warns once because the installer is not code-signed. Choose "More info", then "Run anyway".
Under the hood

What talks to what

The browser never touches the hub. It calls a small JSON API on the tray app, which turns each request into one or more hub commands with validation and range checks.

Things learned the hard way

  • The hub does not answer the Heatmiser app's "hubseek" broadcast on firmware 2218, so discovery sweeps the subnet instead. It takes about a second.
  • The hub keeps one connection happy at a time. All commands go through a single queue.
  • After a ZigBee channel change every thermostat's 24-hour reading buffer is wiped and refills at one sample per 15 minutes. The chart shows gaps rather than zeros while that happens.
  • Only the first poll after start waits for discovery, so a fresh start never logs a false "hub unreachable".

Files

  • main.go: tray menu, discovery loop, browser opening, autostart.
  • internal/hub: the port 4242 client. internal/discover: the subnet sweep.
  • internal/server: the JSON API, action allowlist, status cache, history poller, QR code.
  • public/: the dashboard, plain HTML, CSS and JavaScript with no build step, shared with the Node version used for development.
